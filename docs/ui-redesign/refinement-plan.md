# 晴湾第二轮调整方案

日期：2026-10-25。用户确认：桌面双标签模式使用独立播放窗口。

## 产品行为

1. Windows/macOS：双标签模式为一个浏览主窗口和至多一个独立播放窗口。UGC、影视、直播及离线播放共用播放窗口，新媒体复用窗口，返回沿用有界媒体历史；关闭播放窗口释放其会话并回到原浏览位置。主窗口不显示双标签栏。保留单标签、多标签及有效保存配置。Android 保持应用内浏览/播放两页，不创建桌面窗口。
2. 正式图标使用已有 `assets/branding/app_icon.png`，不重画资源。
3. 桌面侧栏上方为品牌和首页、动态、直播、我的；消息、下载、设置作为固定底部区域。小高度时主导航可滚动，底部入口可达。
4. 动态、直播、我的及其所属频道隐藏通用头像、搜索和历史/下载/设置工具栏；保留各页业务筛选与频道栏。首页头像继续使用原账号抽屉，搜索页继续提供搜索工具。
5. “我的”独立布局：顶部账号资料卡（头像、名称、会员、等级、关注/粉丝/动态），下方观看相关入口（稍后再看、收藏、历史、下载）和账号服务（消息、直播关注、退出）。宽屏居中并分栏，窄屏自动堆叠；游客提供登录及可用入口。复用账号控制器和现有路由，不嵌入抽屉组件，不新增网络/数据库访问。

## 并行边界

- 窗口方案先核对固定 Flutter SDK 官方窗口能力及现有原生入口，选定最小可行方式；只保持一套账号、下载任务和播放所有权，不为窗口重复启动业务服务。
- 代理 A：品牌、侧栏底部固定和通用工具栏可见性，修改 shell 相关区域及布局测试；不改双标签窗口逻辑。
- 代理 B：独立我的页和对应测试；由主代理接入路由，保留首页账号抽屉。
- 代理 C：桌面窗口适配和生命周期，明确与主代理工作区接线的契约；不改代理 A 的侧栏/工具栏区域。
- 主代理：工作区/窗口集成、文档、冲突检查、全量检查、Windows 构建与交互验收。

## 验收

- 单、多模式无回归；双模式无标签栏占位，视频/影视/直播共用一个独立播放窗口；连续打开、返回、关闭、切模式、账号变更、退出不重复播放或泄漏会话。
- 主窗口缩放与页面切换保留状态；320/390/600/桌面宽度与小高度覆盖；窄屏仍只有首页、动态、我的、设置。
- 正式图标和底部固定入口、三类页面工具栏隐藏、我的页登录/游客/错误态与现有所有入口可用。
- 执行根检查和受影响的原生验证、Windows Release。Android/macOS 无设备的项目明确记录，不能把 Windows 结果外推为三端通过。
