# 晴湾第三轮调整

日期：2026-10-25。以本轮用户确认覆盖此前保留单标签和账号入口卡的设计。

## 实现方案

1. 仅保留双标签和多标签。旧 `singlePage` 设置迁移为 `dualTabs`；Android 默认双标签，Windows/macOS 默认多标签，已保存的有效双/多模式不变。共用的页面缓存、浏览返回、媒体历史和关闭语义保留。
2. 桌面播放窗去掉内容区整行“返回／浏览窗口／关闭”。原生标题栏加入一个返回按钮，与系统窗口控制同排；系统关闭按钮关闭播放窗。返回优先媒体历史，历史为空时回浏览窗口；快捷键继续可用。原生拖动、双击最大化和全屏行为保留。
3. 新媒体导航继续复用同一播放窗，并保留用户调整的尺寸及最大化状态。已定位 Windows 固定 SDK 的 `activate()` 无条件执行 `SW_RESTORE`，会把最大化窗口还原；改用按 view 定位的激活适配，仅最小化时恢复。
4. 首页保留头像和搜索：分别承担登录／账号抽屉与全局搜索。移除顶部历史、下载、设置快捷按钮，相关内容从“我的”和侧栏进入；窄屏不恢复这些重复按钮。
5. “我的”采用紧凑账号条与四个内容标签：历史记录、稍后再看、我的收藏、下载。头像／名称仍可打开个人主页，保留等级和登录／退出登录；不显示大资料卡、消息入口或直播关注。内容直接嵌入当前页，复用既有分页、筛选、收藏夹、下载任务与离线播放；四个标签懒加载并保留状态，隐藏内容停止自动分页、绘制与焦点参与。

## 实现边界

- 账号页面只定义标签及内容注入接口，组合根注入历史、首页收藏／稍后再看和下载组件，不让 auth feature 引用其他 feature 的 presentation。
- 单标签退役同步默认值、读写迁移、恢复默认、并发播放条件、快捷键和对应回归；不清除用户数据。
- 标题栏与激活逻辑放平台适配，继续共用一个 engine 和一份媒体会话；不修改 SDK 或 Pub 缓存。
- 保留视频卡、播放控件、评论及全部原有功能入口；Android 窄屏一级导航仍为首页、动态、我的、设置。

## 验收安排

- 由已授权的三个 Sol 6.1 xhigh 代理分别实施导航／首页、窗口、我的页，主代理接线与最终验收。
- 定向覆盖设置迁移、双/多切换、四标签内容状态与懒加载、320/390/600 宽度和大字体、原生最大化／调整尺寸后连续换视频。
- 运行根检查、受影响的 Windows 原生播放及窗口验证，实际 GUI 检查标题栏和“我的”页；构建 Windows Release 和 Android arm64。macOS 构建及实机、Android 实机仍需对应设备，分别记录。

后续范围修订：用户在自动检查通过、Windows GUI 检查进行中明确要求停止实机/界面测试，完成单元回归与构建后由用户手动验收。之后不再操作应用窗口或追加设备验证；已完成及未完成步骤分别记录在实施记录中。
