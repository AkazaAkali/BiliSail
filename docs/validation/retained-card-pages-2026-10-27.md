# 多页面深滚动与共享卡片更新（2026-10-27）

## 定位与改动

在推荐页局部更新优化后，继续检查热门、搜索、历史、视频动态、收藏、稍后再看和空间等共用卡片路径。使用 3 个各加载 300 条数据的实际路由页面检查保留状态；普通视频列表仍然只挂载视口和缓存区附近的行，未发现将全部已加载卡片 Widget 长期保留的问题。

本轮修改：

1. `Offstage` 隐藏页面不会结束 `ScrollPosition` 的触摸惯性活动。原有共享滚轮实现只停止自有桌面滚轮动画，Android 的隐藏列表仍继续滚动、布局和创建新行。共享滚动装饰现在在页面失活后结束纵向滚动，保留控制器、数据和当前位置；越界回弹收敛到合法边界，横向分页动效仍由分页器管理。
2. `SliverVideoGrid` 或首页列表追加数据时，未变化的可见 `VideoCard` 内容仍然被重新构建。共享卡片现在比较实际展示/预览字段，只在内容、交互状态或依赖改变时更新卡片主体；点击、作者、菜单和撤销动作通过当前 State 转发，避免旧历史索引、旧队列或旧登录回调。缓存只属于已挂载卡片，随视口淘汰释放。
3. 动态列表使用完整 `MediaQuery` 订阅，并在任意依赖通知时清空所有已测量高度。键盘 inset 或窗口高度变化会导致每个保留列表重新同步排版全部已加载动态。现在仅跟踪文字布局相关依赖，宽度和系统字体变化仍重新测量，保留展开状态、精确滚动条范围与自然高度。
4. 卡片复用后，共享行列表主动更新滚动范围，避免可见卡片尺寸不变时沿用分页前的旧范围。空间收藏夹的原有末尾定位测试捕获了这个关联问题，修正后仍能直接跳到追加页最后一项。

## 回归验证

- 共用视频列表追加视口外数据：原先重建 12 个已有标题，优化后 0 个；同时验证新点击、作者和删除回调及滚动范围增长。
- 深滚动到 10,000 像素后甩动并隐藏：原先 200 毫秒内额外滚动约 911 像素，优化后停止，返回后继续接受拖动。
- 300 条动态仅修改键盘 inset：原先构建 306 次动态卡片（含 300 次离屏测量）；优化后不再全量测量。字体缩放、系统粗体、主题和字体变化仍更新高度。
- 新增实际工作区多列表回归：推荐、视频动态、稍后再看滚深并反复切换，验证控制器/位置保留、隐藏滚动停止和挂载卡片数有界。
- 原有卡片菜单、悬停、自然高度、动态展开与滚动条、收藏及稍后再看回归继续覆盖。

## 真机采样方法

`integration_test/android_retained_cards_test.dart` 使用实际路由、页面和共享滚动行为，内存仓储提供 3 组各 300 条数据，每页封面 URL 分离；封面为固定 480×270 PNG，不发起账号读写。每页先滚动约 12,600 逻辑像素，再重复 6 轮甩动、立即切页并滚动下一页，采集 UI/raster 帧耗时和隐藏页位移。

```powershell
./tool/test-android-primary-switch.ps1 -DeviceId <id> -Scenario retained-cards -Label <label> -SkipMuxBuild
```

测试使用独立 `dev.bilisail.bilisail.test` Profile 包；脚本先保留普通入口开发 Release，结束后覆盖恢复，保留测试包数据和设备原有常亮设置。固定图片/数据对照用于比较结构开销，不能代表真实网络、所有设备或长期高刷流畅度验收。

## 采样结果与限制

设备为 Xiaomi 13（2211133C / Android 16 / 120 Hz）。有效结果为 `build/validation/retained-cards-before-final.json` 和 `build/validation/retained-cards-after-first.json`，每版 18 个样本；此前有探针订阅 `WorkspaceActivity` 导致 ScrollPosition 替换的问题，相关失败轮次已丢弃。正式探针使用不建立依赖的继承组件读取。

| 指标（毫秒） | 修改前 | 修改后 |
| --- | ---: | ---: |
| 各样本 UI 峰值的中位数 | 20.721 | 22.366 |
| 各样本 raster 峰值的中位数 | 18.791 | 18.277 |
| 全部采样帧 UI P95 | 9.367 | 9.809 |
| 全部采样帧 raster P95 | 8.905 | 9.972 |

这组深滚动/切页对照**没有证实整体帧耗时下降**，仍存在超过 120 Hz 的 8.33 毫秒预算的帧。前后最多挂载 44 / 42 张视频卡片，没有随 900 条已加载数据增长；18 轮离开页位移前后都为 0，不能把孤立 Offstage 用例的惯性问题认定为当前底栏路径卡顿的根因。卡片追加和动态高度缓存的收益由独立重建/测量回归证明；真实账号、多页长时间浏览的主观卡顿仍需后续复测与更细的运行时归因。

上述 Profile 不包含随后补上的滚动范围刷新与系统粗体缓存回归，这两项通过 Widget 验证及最终开发 Release 构建验证。额外 CPU 采样请求没有取得可用于归因的数据，不作为性能结论。
