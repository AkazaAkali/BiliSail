# 弹幕高刷合成开销定位与修复

日期：2026-10-13。问题由[真实首页视频复测](windows-real-video-gpu-2026-10-13.md)定位，测量采用 Windows Release、RTX 4070 Ti SUPER、1080p，沿用该视频与实际设置，每个场景稳态采样 30 秒。

## 原因与对照

首页选中的 [BV1C3576fErj](https://www.bilibili.com/video/BV1C3576fErj/) 在 30–60 秒片段最多只有一条滚动弹幕，文字图像缓存命中超过 99.9%，直接文字绘制回退为 0。弹幕出现时 Flutter 帧时序从约 30 次/秒升至约 180 次/秒。全屏有弹幕子区间的 3D 均值为 23.76%，空档约 4.69%；全屏整个 30 秒为 10.06%。子区间仅约 7 个完整 GPU 点，不能当作 30 秒持续密集弹幕数据。

保持正式页面、解码、物理输出尺寸、字体、阴影、粗体及 180Hz 调度，只把内存偏好中的透明度 0.8 改为 1.0。标签 `real-opacity-1`：窗口内有弹幕子区间 7.34%，全屏 23.98%；全屏 30 秒均值 9.77%。GPU 同为 210MHz/P8。对比原来的 7.40% / 23.76%，没有支持“整层透明度是主要瓶颈”的证据，因此保留原来的透明度及重叠绘制语义。

主要可复现成本是 **高刷弹幕驱动整个 Flutter 视频窗口高频绘制和合成**。`RepaintBoundary` 可以隔离弹幕层重绘，视频仍通过 Flutter 纹理合成到同一窗口。本轮没有跟踪网页的实际视频 overlay 使用情况。这里的 180 次 Flutter 帧不能换算成 180 次原生解码、GPU 回读或纹理复制；本轮不改变已验证的 Windows 硬解与原生同步路径。尚未进行逐 GPU pass 计时。

## 实现

- 点播和直播共用 [DanmakuFrameDriver](../../packages/bili_danmaku/lib/src/danmaku_frame_driver.dart)，用 17ms 的有界计时器驱动滚动绘制，不再由连续 Ticker 按屏幕最高刷新率请求帧。Windows 原生 Dart Timer 将 16.667ms 截断为 16ms，初测实值为约 62.5 次/秒；最终实现向上取整到 17ms，保持 60 次/秒以内。动画计时期间的确认位置/消息合并，位置从原时钟读取；不会按 tick 累加时间或降低播放位置事件频率。
- 每次读取帧比较文本身份、位置和文字样式，只有画面变化才通知 CustomPainter。顶部/底部固定弹幕和播放确认位置相同的帧不重绘，固定到期与未来到达使用单次唤醒。
- 点播保持有界插值、暂停/缓冲/seek 冻结和倍速语义；直播保持收件时钟。两种 overlay 都遵守 TickerMode，停用、换控制器和 dispose 取消计时器；DPR 变化由画家更新，原图像缓存与预算不变。

60Hz 是此次功耗取舍：高刷屏的弹幕刷新频率降低，文字速度、寿命和时间对齐保留，未声称与 180Hz 视觉完全等价。全窗合成的剩余成本仍存在；若必须保留 180Hz，需要另行验证平台独立视频/弹幕合成层。

## 验证和产物

提交前整合时发现当前工作区的两种 overlay 仍在使用旧 Ticker，已有帧驱动未接入，导致新增 9 项回归失败。已补齐共用驱动、固定项到期／未来到达唤醒以及 TickerMode 停用，并更新旧空闲测试以验证 17ms 计时器后的实际绘制。弹幕包 100 项测试通过。本节 GPU 数字来自此前保存的 Release 探针构建；本次整合没有重新执行 GPU 测量，不能将历史候选数据当作本次全部修改同产物的新实测。

最终 17ms 实现的两轮复测如下。修复前采用同频率的 `real-home-2`，修复后标签 `real-final-1` / `real-final-2`；所有表格场景均为 **210MHz/P8**。每场景 30 条播放样本，实际 30.000–30.013 秒，获得 28–29 个完全位于阶段内的 GPU 间隔。

| 场景 | 修复前 3D 均值 | 修复后第 1 轮 | 修复后第 2 轮 |
| --- | ---: | ---: | ---: |
| 窗口内，关闭弹幕 | 1.43% | 1.41% | 1.49% |
| 窗口内，开启真实弹幕 | 3.10% | **1.93%** | **1.93%** |
| 全屏，关闭弹幕 | 4.46% | 4.60% | 4.56% |
| 全屏，开启真实弹幕 | 10.06% | **6.18%** | **6.09%** |

两轮全屏开启弹幕的 30 秒均值降低约 **39%**，窗口内降低约 **38%**；关闭弹幕的基线基本不变。不能将均值降低写成所有视频固定降幅。

按相邻每秒采样均有弹幕筛选的可见子区间（各约 6–7 个 GPU 点），窗口内 7.40% → **3.30% / 3.31%**，全屏 23.76% → **10.58% / 10.38%**，全屏下降约 **56%**。这些值是整个 30 秒里的短子区间，不是持续 30 秒有弹幕的均值；入场/退出边缘的可见状态仅按秒采样。

滚动文字实测每秒绘制约 **58–59 次**；Flutter 总帧时序仍包含视频纹理更新，实际有弹幕时窗口内约 78 次/秒、全屏约 74–76 次/秒，**不能声称整个窗口严格降到 60fps**。30 秒总均值约 41–43 次/秒，纯视频仍约 30 次/秒。两轮均没有 buffering/seeking、播放器/解码器掉帧或 Flutter 错误，最大绝对 A/V 偏差不超过 1ms，图像命中率约 99.79%，直接绘制回退为 0。

`tool/check.ps1 -SkipPub` 的格式、静态分析及 **2514 项测试**通过：根应用 1932、API 426、播放器 54、弹幕 100、合流 2；10 项依赖 `BILI_MUX_LIBRARY` 的合流原生测试按未配置跳过。本轮没有修改 native 播放代码。Windows Release 探针与正常 `lib/main.dart` 产品入口均构建成功；正常入口恢复在 `build/windows/x64/runner/Release`。

新增模拟 180Hz 的点播/直播、滚动/顶部/底部刷新测试，固定到期/未来滚动唤醒、隐藏标签停用与当前时间恢复回归；已有空弹幕、暂停、缓冲、seek、倍速、预算、像素效果和 DPR 回归继续执行。

真实复测使用同一 BV、登录信息和持久设置的内存副本，实际源仍为 DASH H.264/AAC、qn=80、1920×1076、`d3d11va`。窗口 1280×720，全屏 1920×1080，输出纹理分别 896×503 / 1920×1076；没有修改或记录 Cookie、签名媒体 URL 或弹幕正文。

GPU、帧时序、解码、频率和功耗分别保存于 `build/validation/windows-*-real-final-*.jsonl`、`windows-real-clocks-real-final-*.csv` 与产物哈希。GPU 采用连续一秒 PDH 查询，只统计完全处于阶段内的间隔；报告 30 秒播放样本与 GPU 完整点数。最终构建/测试日志在 `artifacts/windows-gpu-native/danmaku-final-*.log`。`real-fixed-1` / `real-fixed-2` 为修正 Timer 毫秒精度之前的初测，不作为最终实现的验收数字。
