## 2026-10-22：图片可见性与标题测量

接续同日的悬停/单卡隔离修复，本轮优化共享图片和标题路径，未改变列表高度、滚轮阻尼、缓存容量、预取距离或网络协议。

- [AppNetworkImage](../../lib/shared/ui/app_network_image.dart)将同一 `ScrollPosition` 的图片监听合并为一份，所有失效图片在一个帧后回调中检查。隐藏图片移除滚动监听；移出组件树时清除待检查项、旧视口祖先和监听，移回后重新绑定。
- 每张图片只缓存视口祖先关系，布局、依赖或树位置变化即失效；实际坐标每轮重算。一次检查内共享视口边界和最近视口到外层视口的变换矩阵，矩阵先组合再计算图片边界，避免旋转后的矩形逐次放大。矩阵和像素坐标不跨帧保留。
- 同步滚回时的已解码帧准入继续即时执行，未完成/未缓存图片仍等布局确认，并保留快速滚动延期、可见/预取优先级、离屏取消、160px 预取和隐藏页帧保留。批次内单张图片检查异常照常报告，但不阻塞其他图片。
- [HighlightedText](../../lib/shared/ui/highlighted_text.dart)对已挂载且启用溢出提示的标题保留一份测量结果，用 Flutter `TextSpan.compareTo` 区分仅绘制变化与排版变化。悬停/高亮颜色变化复用结果；文本/高亮结构、可用宽度、字体、字号、字距、粗体、缩放、方向、语言、行数和高度行为变化重新检查，字体加载通知也会失效。不开启 tooltip 的文本没有新增测量缓存。
- 检查其他页面时，发现[共享播放时间轴](../../lib/features/playback/presentation/playback_timeline_bar.dart)的章节标题也会随进度/悬停更新重复测量。本轮按当前章节缓存自然尺寸，宽度变化只重算是否放得下；字体/缩放/方向/语言、章节列表或播放来源变化时失效，字体监听在销毁时释放。测量使用与实际 Text 一致的继承样式和粗体，缓存最多覆盖当前规范化的 200 个章节。视频与影视共用该时间轴。

复用范围：封面、头像、首页/空间动态、评论图片和表情、直播聊天/表情、时间轴缩略图均经共享 `AppNetworkImage` 生效；推荐、搜索、历史、收藏/稍后再看及播放页相关推荐的标题经共享 `HighlightedText` 生效。播放器控件已有布局输入缓存，稍后再看队列的行高测量属于布局变化路径，未另改其行为。

## 定位与实现

推荐页原来用 `SliverToBoxAdapter → Column → VideoGrid → Wrap` 一次创建全部已加载卡片。500 条数据时，滚动仍遍历全部卡片的绘制与图片可见性探针；去掉图片后 UI P95 仍为 24.50–24.99 ms，因此主要热点是列表结构。首次离开顶部和分页状态切换还会重建全部卡片，封面三个标签的 `TextPainter` 测量进一步放大突发开销。

修复包括：

- 推荐、热门、分区、排行榜使用 `SliverVideoGrid`；动态使用 `SliverList.builder`，视频动态、番剧、国创、直播、放映厅、收藏、稍后再看等首页子标签使用 `SliverResponsiveCardGrid`。搜索的七种分类和云端观看历史同样改为懒创建列表。
- 网格按行创建，保留自然高度、窄屏两列、宽屏列数和文字缩放规则。滚动约束变化时复用同一行委托，并利用行级绘制边界；数据、卡片动作和横向布局改变时才更新委托。
- 回顶部按钮通过局部 `ValueListenableBuilder` 更新。分页等待、失败和重试只更新尾部，数据未变时复用卡片主体；刷新、换查询、账号状态变化和整页空/错误态清理主体缓存。
- 视频封面标签按实际字体、文字缩放、方向、locale 和文本缓存宽度，每张已创建卡片最多 9 项；字体加载后失效，仍通过真实文本宽度决定布局。

领域列表、分页游标和原有账号/请求隔离保持原策略。UI 虚拟化只减少已创建组件；稍后再看播放队列仍取完整领域列表，历史记录仍按条目索引保留不同分 P 的播放身份。

## 2026-10-07 动态单图滚动位移修复

动态单图原来只有 `maxWidth: 320` / `maxHeight: 360`，高度由图片解码结果决定。`AppNetworkImage` 在图片离开视口前后 160 像素的加载区域后改用空占位，单图高度随之归零；滚回或懒列表重新创建卡片时，高度再次恢复。这会改变 `SliverList` 中后续条目的布局，与滚动输入无关。实际 `HomeContent` 的模拟图片探针复现了滚动位置保持 420 像素、相邻两帧内容额外上移 160 像素的现象。

修复由 API 解析 `draw.items` / `opus.pics` 的 `width`、`height`，经不可变的 `imageAspectRatios` 传到共享动态卡片。单图使用 `AspectRatio` 在加载前预留空间，继续受 320×360 上限和可用宽度约束；缺少合法比例时始终使用方形占位，解码完成也不改变占位尺寸，图片按原比例完整显示。图片隐藏、失败或卡片重新创建时保留同样的布局。共用卡片同时覆盖首页、空间动态和转发引用；多图网格与原图预览沿用既有布局和加载边界。

尺寸字段支持数字及数字字符串；零、负数、非有限值及除法溢出被忽略。本轮没有改变端点、请求次数、鉴权或分页策略。字段形态参考项目此前保存的脱敏 `artifacts/dynamic-schema-probe.log`：`draw` 使用字符串宽高，`opus` 使用数值宽高；该日志是前序在线证据，本轮未重新请求真实账号动态。

行为回归覆盖“全部”／“图文”两子标签中的横图、竖图、长图、缺少尺寸、图片失败与转发图片，逐帧检查首次解码、离开加载区域、滚出缓存区后返回的卡片高度和后续卡片位置，同时检查屏幕外卡片仍被懒列表释放。协议测试覆盖首页／空间的两种图片格式、非法尺寸和不可变比例映射；共享映射验证转发原动态保留自己的图片比例。

## 2026-10-08 动态滚动条范围修复

动态卡片本身保留自然高度，但普通 `SliverList.builder` 按当前已布局行的平均高度推算剩余内容。可见区域从短文本切到长图、多图或转发时，同一批数据的 `maxScrollExtent` 会改变，滚动条长度和拖动位置随之跳变。

首页“动态”的全部／视频／图文及空间动态改用[共享动态列表](../../lib/shared/ui/sliver_dynamic_post_list.dart)。它用同一张动态卡片的布局测量已加载条目的自然高度，缓存后将准确总高度提供给 Sliver 委托。测量树逐条复用并销毁，只放置图片尺寸占位，不请求图片、不订阅账号交互状态，也不挂载到页面或绘制。实际交互卡片仍按视口懒创建、屏幕外释放。分页只测量新增或改变的条目；滚动复用高度和委托，窗口宽度、字体、主题、locale、文字缩放改变时重新测量。

展开正文的状态由该列表保留，卡片被释放后返回仍沿用展开状态。真实内容高度变化会更新记录；分页追加、正文展开及布局条件改变允许滚动范围随内容更新。委托更新显式触发布局，避免只在尾部增加数据时沿用旧范围。另给行内表情固定尺寸容器，防止加载失败的文字回退改变行高。

[六项滚动条回归](../../test/features/feed/dynamic_scrollbar_test.dart)覆盖三种动态子标签的高矮混排、跨首尾反复跳转、真实鼠标手势连续上下拖动、正文展开后释放／重建及宽度／文字缩放变化、追加分页后的原位置保留。逐帧检查同一批数据的总范围、滑块比例与位置，保留屏幕附近的卡片数量上限。测试使用模拟仓储，图片网络由 Flutter 组件测试环境返回失败，不请求真实账号或在线接口。

`tool/check.ps1 -SkipPub` 通过：根应用 1,328、`bili_api` 319、`bili_player` 32、`bili_danmaku` 65 项，共 1,744 项测试；四处格式和静态分析通过，文档相对链接和 `git diff --check` 通过。专项六项回归包含在根应用检查中。
